# `NewASM` Release Notes
Welcome to **`NewASM`**: interpreted low-level language that mimics assembly.

- Version: `2.0.0`
- Release: `1`
- Release type: `beta`
- System build number: `3`

*NOTE*: This is a pre-release which means that this product version doesn't represent the final quality of the product - it may contain bugs and problems that aren't yet discovered.

## What's new

The new update unveils various changes regarding the syntax, instructions and more!

* Opcodes are now added as an other way to write instrucions, instead of `mov` you can do:
```asm
0x1 tlr, 1
```

* Added the new `malloc` and `free` instructions to manage heap memory more easily. Instead of having to remember how much memory you have allocated using `heap`, you just allocate and let the program free it for you:
```asm
.data
num $ testvar = 9279 ; some important value
.start
malloc 1 ; allocate more space
mov hea, [0] ; access the first address inside an allocated part of the heap memory
load adr, testvar ; save the value for later
; do someting with testvar
load ref, testvar ; reset testvar back to its original value
free ; free up the space reserved using malloc
retn 0
```

As you may have noticed, we used the `[]` brackets to access the addresses only within the allocated heap memory using `malloc`.

* Now you can make your own events using hex codes and the stack memory! Also added the new `stack` instruction.
```asm
.hndl
0x827, procedurename
.start
proc procedurename
mov tlr, <0> //get the first argument
mov stl, <1> //get the second argument
mov fdx, 1
syscall 0, %ios
end
push 0, %endl // push the second arg
push 0, “string” // push the first arg
push 0, 0x827 // call the procedure
stack //clear up the stack after the procedure call
```
Pushing hex codes to the stack is the same as `call`, but with function arguments. In order to get the arguments correctly, you have to push from the back.

Added the new `wait` instruction. Example:
```asm
.start
wait 2000 ; waits for 2000ms, or 2s
retn 0 ; ends the program
```


## What's changed

* Several instructions have had their suffix (argument 1) component removed, so you can simply do:
```asm
instructuion argument
```
Instructions affected by this are `heap`, `proc` and `call`.

* Introduced the new code section syntax, instead of doing:
```asm
_:start
nop
retn 0
```
you can simply do:
```asm
.start
nop
retn 0
```
* Introduced the new `data` section syntax:

```asm
.data
num variable: 1
.start
mov tlr, variable
mov stl, %endl
mov fdx, 2
syscall 0, %ios
retn 0
```

* Changed the jump label syntax from:
```asm
_!label
```
to:
```asm
:label
```

## Fixed issues

* Fixed the `~exit` event.

### Building from source
- Use the following command to compile your own build of `NewASM`; make sure that you have G++ installed:

```bash
C:\path_to_your_compiler\g++ -static -std=c++20 index.cpp -o index.exe
```

- If you are using Windows Subsystem for Linux, use the following command:

```bash
wsl g++ -m32 -static -std=c++20 index.cpp -o index.out
```

### Downloading
- Download one of the following archives that suits your system. Once you have downloaded it, extract the archive into a folder of your choice and begin using the application.

### Using the application
- Use the following command to execute your `NewASM` programs on Windows:

```bash
newasm -input yourfile.asm
```

- If you are on Linux, just add the `.out` extension:

```bash
./newasm.out -input yourfile.asm
```

### Writing your first `NewASM` app

- Create the file named `yourfile.asm`, or just name it whatever you like, and edit it with an editor of your choice:

```asm
.data
    txt string : "Hello world!"
.start
    mov tlr , string
    mov stl , %endl
    mov fdx , 1
    syscall 0 , %ios
    retn 0
```

Output:
```
Hello world!
```
