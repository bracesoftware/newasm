# `NewASM` Release Notes
Welcome to **`NewASM`**: interpreted low-level language that mimics assembly.

- Version: `2.1.0`
- Release: `1`
- Release type: `beta`
- System build number: `4`

*NOTE*: This is a pre-release which means that this product version doesn't represent the final quality of the product - it may contain bugs and problems that aren't yet discovered.

## What's new

* Added the new `sysenter` instruction to redirect the system calling to a specific module.
```asm
mov tlr, msg ; some message
mov stl, %endl ; \n
mov fdx, 1 ; fdx for sys_write / print
sysenter %ios ; enter the ios module
syscall ; perform the system call
```
* Added the new `.text` section used to define macros.
```asm
.hndl
    0x73, testproc
.data
    num testnumber : 8272
    struct teststruct : {
        num testnumber : 4267
    }
.text
    sayhello : # ; start of macro
        mov tlr, “hello”
        mov stl, %endl
        mov fdx, 1
        sysenter %ios
        syscall
    # ; end of macro
.start
    mov tlr, 10
    int 0x1
    sayhello
    retn 0
```

* Added the new `xchg` instruction — exchanges `tlr` and `stl` register values.
```asm
.start
mov tlr, 19
mov stl, 29
xchg
db stl ; prints 19
ret tlr ; returns 29
```
* Added the new `int` instruction for system interrupts. Allows you to manipulate with the interpreter configuration within the `.start` section.
```asm
mov tlr, 82 ; new memsize
int 0x1 ; modify the memsize
```

Complete list of currently available system interrupts:
| ID | Arguments | Description |
| ---------------- | --------- | ----------- |
| `0x1` | `tlr` | Modifies the size of a shared heap-stack memory block, with `tlr` holding the new memory size. |
| `0x2` | `tlr` | Tells the interpreter to skip checking for procedure validity when assigning event handlers with `tlr` being either 0 or 1 — off or on, respectively. |

* Added the new `cls` instruction, clear the screen.
```asm
.start
cls
```

* Added the new `%chrono` system call module to get information about time.
| Module | `fdx` | Arguments | Description
| --------------- | ---------------- | --------- | ----------- |
| `%chrono` | `1` | `/` | Gets the current year and stores it in `tlr`. |
| `%chrono` | `2` | `/` | Gets the current month and stores it in `tlr`. |
| `%chrono` | `3` | `/` | Gets the current day in a month and stores it in `tlr`. |
| `%chrono` | `4` | `/` | Gets the current hour and stores it in `tlr`. |
| `%chrono` | `5` | `/` | Gets the current minute and stores it in `tlr`. |
| `%chrono` | `6` | `/` | Gets the current second and stores it in `tlr`. |

* Added the new `retf` instruction and swapped functionalities of `ret` and `retn`.
`ret` is now just a value return;
`retn`, or “near return”, returns register values;
`retf`, or “far return”, returns something from a thread.
Also added the `await` instruction.
What `await` does is that it stops the `.start` execution till the thread finishes, while return-far (`retf`) returns a value within the thread.
To print the thread output in the console, you have to use the thread-system calls - same with the returned value.
Exampe:
```asm
.data
    txt string : "LOL"

    thread  testthread : {
        mov tlr, "Hello from thread"
        mov stl, %endl
        mov fdx, 1
        sysenter %ios
        syscall
      
        mov fdx, 1
        sysenter %chrono
        syscall

        mov fdx, 2
        mov stl, %endl
        sysenter %ios
        syscall

        mov tlr, "hi again"
        mov fdx, 1
        syscall

        mov tlr, "this was returned"
        stor tlr, string
        retf string

        sysenter %ios
        mov tlr, "YOU SHOULD NOT SEE THIS"
        mov stl, %endl
        mov fdx, 1
        syscall
    }


.start
    await &testthread ; wait for the thread to finish immediatelly
    ;if the thread doesn't finish, we will get ExpectedAwait error
    sysenter %thread
    mov fdx, 1
    mov tlr, &testthread
    syscall ; display the thread output
    mov fdx, 2
    syscall ; fetch returned value
    sysenter %ios
    mov stl, %endl
    mov fdx, 1
    syscall ; print the returned val
```

Output:
```
Hello from thread
2025
this was returned
```

## What's changed
* Since `int` takes care of interpreter configuration and manipulation, `.config` section is removed.
* A lot of backend optimization.
* The way threads function is changed.


## Fixed issues
* Fixed threads — now you can use them as they were intended.

### Building from source
- Use the following command to compile your own build of `NewASM`; make sure that you have G++ installed:

```bash
C:\path_to_your_compiler\g++ -static -std=c++20 index.cpp -o index.exe
```

- If you are using Windows Subsystem for Linux, use the following command:

```bash
wsl g++ -m32 -static -std=c++20 index.cpp -o index.out
```

### Downloading
- Download one of the following archives that suits your system. Once you have downloaded it, extract the archive into a folder of your choice and begin using the application.

### Using the application
- Use the following command to execute your `NewASM` programs on Windows:

```bash
newasm -input yourfile.asm
```

- If you are on Linux, just add the `.out` extension:

```bash
./newasm.out -input yourfile.asm
```

### Writing your first `NewASM` app

- Create the file named `yourfile.asm`, or just name it whatever you like, and edit it with an editor of your choice:

```asm
.data
    txt string : "Hello world!"
.start
    mov tlr, string
    mov stl, %endl
    mov fdx, 1

    sysenter %ios
    syscall
    ret 0
```

Output:
```
Hello world!
```
